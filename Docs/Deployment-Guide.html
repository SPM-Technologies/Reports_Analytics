Deploying the Patient Registration system

Step-by-step instructions for anyone: take the project from Git, install the one prerequisite (Docker), start the system, load the demo data, and check that every part works. No Java, Maven, Node or database installation is needed.

Repository: https://github.com/SPM-Technologies/Reports_Analytics (private: you need access). Commands are for Windows (PowerShell or Command Prompt); Linux/macOS equivalents are in section 16.

1a. Java, Maven, Node and Tomcat: provided by Docker

You do not install Java, Maven, Node or Tomcat. They come inside Docker images, defined in the project's Dockerfile, and are downloaded automatically by start.bat the first time. The application image is built in two stages:

SoftwareVersionWhere it comes fromConfigured in
Java (JDK, Eclipse Temurin)21both images (maven:...-eclipse-temurin-21, tomcat:...-jdk21-temurin)Dockerfile
Maven3.9.9build image maven:3.9.9-eclipse-temurin-21; libraries downloaded from Maven Central during the build and kept in a Docker build cacheDockerfile, pom.xml files
Node + npm20.18.1 / 10.8.2downloaded by Maven's frontend plugin during the buildpr-ui/pom.xml
Tomcat11.0.27runtime image tomcat:11.0.27-jdk21-temurinDockerfile (memory -Xms256m -Xmx512m, time zone Asia/Kolkata)
Application (WAR)this projectbuilt in stage 1, deployed as /patient-registrationDockerfile, settings via docker-compose.yml / .env
PostgreSQL, ClickHouse, Kafka, Debezium18.6, 25.3.14.14, 3.9.0, 3.0.0their official imagesdocker-compose.yml

Check them on a running system:

docker exec pr-app java -version                                       # openjdk version "21..."
docker exec pr-app sh -c "grep 'Apache Tomcat Version' /usr/local/tomcat/RELEASE-NOTES"   # 11.0.27
docker compose logs app | findstr /C:"Server version name"             # Tomcat start-up line
The repository also contains tools\ (Maven 3.9.9, Node and a library cache). These are not used by Docker (they are excluded from the build); they are only for developers who build or test on Windows outside Docker, together with a locally installed JDK 21 (section 9.6).

3. Prepare the machine

1

Install Git

Download Git for Windows from https://git-scm.com/download/win and install with the default options. Check in a new PowerShell window:

git --version            # e.g. git version 2.5x
2

Install Docker Desktop

Download from https://www.docker.com/products/docker-desktop/, install with "Use WSL 2" selected, restart Windows if asked, then start Docker Desktop and wait until it shows "Engine running".

docker --version
docker compose version   # must print "Docker Compose version v2..."
docker run --rm hello-world
3

Give Docker enough memory

With WSL 2 the memory is set in %UserProfile%\.wslconfig (create it if missing), then run wsl --shutdown and start Docker Desktop again:

[wsl2]
memory=6GB
processors=4

Check: Docker Desktop → Settings → Resources shows the limit; docker info prints Total Memory of at least 4 GB.

4

Make sure the ports are free

netstat -ano | findstr ":8080 :5432 :8123 :8083"

No output means the ports are free. If a line shows LISTENING, stop that program (for example a Windows PostgreSQL service or another Tomcat) before continuing.

4. Get the project from Git

5

Clone the repository

Choose a folder without spaces, preferably on a drive with enough space (for example D:\Projects):

cd D:\Projects
git clone https://github.com/SPM-Technologies/Reports_Analytics.git
cd Reports_Analytics

The first time, a GitHub sign-in window appears (Git Credential Manager): sign in with an account that has access. The download is about 450 MB because the repository also holds the bundled build tools (tools\) and the database backups (backup\).

Clone with Git (not "Download ZIP"): the repository's .gitattributes makes sure the Linux scripts used inside the containers keep their correct line endings. A ZIP extracted on Windows can break them.
6

Check what you received

dir
#  backup\  db\  Docs\  infra\  pr-app\ ... tools\
#  docker-compose.yml  Dockerfile  .env  start.bat  stop.bat  deploy.bat  restore.bat  backup.bat  load-data.bat  README.md
git log --oneline -3

All passwords and options are in the file .env in the project folder. The defaults work as they are for a local demo:

Change the passwords before the first start if the computer is shared or reachable from a network. The PostgreSQL administrator password is fixed when its data volume is created; changing it later needs a fresh volume. Set DEMO_DATA=false for an installation without demo users.

6. Deploy step by step

7

Start the system

In the project folder (Docker Desktop must be running):

start.bat
# same as: docker compose up -d --build

The first start downloads the images and builds the application inside Docker: about 8-15 minutes (measured 8 min 39 s on a test laptop). Later starts take about 1-2 minutes.

8

What happens automatically

  1. PostgreSQL and ClickHouse start; ClickHouse creates its databases analytics and analytics_test on the first start.
  2. The application starts and creates or updates all tables, security rules and the report templates; it creates the user admin and (with DEMO_DATA=true) hospitals H002, H003 and the demo users.
  3. When the application is healthy, pg-setup creates the pipeline accounts and the test database, then analytics-setup prepares ClickHouse and the one-minute copy. Both then stop ("Exited (0)") — that is correct.
9

Wait until it is healthy

docker compose ps -a

Expected:

pr-app          Up ... (healthy)
pr-clickhouse   Up ... (healthy)
pr-postgres     Up ... (healthy)
...-pg-setup-1          Exited (0)
...-analytics-setup-1   Exited (0)

If pr-app shows (health: starting), wait a minute and run the command again.

10

Open the application

http://localhost:8080/patient-registration/ → sign-in page. Sign in as admin / Admin@1234. At this point the system is running without patients; load data in the next step.

7. Load the data

Choose one of the two options.

Option A — the exact demo data (recommended)

The repository contains the full demo data set in backup\patientreg_full_2026-10-16_1726.dump (22 MB): H001 1,00,002, H002 20,000 and H003 10,000 patients, all users, settings and saved reports.

certutil -hashfile backup\patientreg_full_2026-10-16_1726.dump SHA256
#  must print 5eb7c11e3fb09084e79871119944e35fb08c0a76be5a67d5660f6bc936b9f72b

restore.bat backup\patientreg_full_2026-10-16_1726.dump
#  type YES when asked; takes about 1-2 minutes

restore.bat stops the application, replaces all data in PostgreSQL with the backup, empties ClickHouse, starts everything again and lets ClickHouse copy all patients. After it, the users and passwords of the backup apply (see section 9.2).

Option B — generate new test patients

load-data.bat 100000 1      # 1 lakh patients for H001 (about 1 minute)
load-data.bat 20000 2       # H002
load-data.bat 10000 3       # H003

The patients are realistic but fictitious, with every field filled; ClickHouse is reloaded automatically after each run. Running it again adds more patients.

Option A is needed if you want to run the browser test suite: it checks the exact demo counts (1,00,002 / 20,000 / 10,000).

8. Real-time reports (optional)

Without this option, a new registration appears in Analytics within about one minute. With it (Kafka + Debezium), within a few seconds.

start.bat cdc
# same as: docker compose --profile cdc up -d --build

The first time this downloads two more images (about 2.8 GB). Expected afterwards in docker compose ps -a: pr-kafka (healthy), pr-debezium (healthy), ...-ch-cdc-setup-1 Exited (0), ...-cdc-setup-1 Exited (0).

After using the real-time option once, always start with start.bat cdc. If you decide to stop using it permanently, remove its database slot so PostgreSQL does not keep change log for it: docker exec pr-postgres psql -U postgres -c "SELECT pg_drop_replication_slot('pr_outbox_slot')".

9. Verify everything works

9.1 Containers

docker compose ps -a
  • pr-app, pr-postgres, pr-clickhouse are Up (healthy) (and pr-kafka, pr-debezium with real time)
  • every ...-setup-1 container is Exited (0) (any other exit code: see troubleshooting)
  • docker compose logs app | findstr /C:"Database schema applied" prints one line, and docker compose logs app | findstr SEVERE prints nothing

9.2 Sign in

UserPasswordShould see
adminAdmin@1234all three hospitals; Administration and Settings menus
h001.adminDemo@1234only H001, with Settings and Administration
h002.reportsDemo@1234only H002 reports; no registration
group.reportsDemo@1234"3 hospitals" in Analytics
  • each of these users can sign in, and a wrong password shows "Wrong username or password"

9.3 Screens

  • Dashboard (/patient-registration/) shows the patient count of the working hospital (H001: 1,00,002 with option A)
  • Reports → Patient Register lists patients, 50 per page, and the Excel download opens
  • Reports → Department Summary shows departments with a grand total
  • Analytics (/patient-registration/app/) opens the "Patient Register (Report 1)" template; the header shows "Data as of" with a recent time
  • Analytics as h001.reports: the template "Department Summary (Report 2)" shows a total of 1,00,002 (option A; as admin or group.reports the total covers all three hospitals: 1,30,002), and its Chart button draws a chart
  • Settings (as h001.admin) opens Form fields, Dropdown lists, Departments, Report fields, Downloads
  • Administration (as admin) lists users, hospitals, roles and the audit log

9.4 Data in both databases

docker exec pr-postgres psql -U postgres -c "SELECT hospital_id, count(*) FROM patientreg.patient GROUP BY 1 ORDER BY 1"
docker exec pr-clickhouse clickhouse-client --user admin --password ChAdmin@1234 -q "SELECT hospital_id, count() FROM analytics.patient_report FINAL WHERE is_deleted = 0 GROUP BY 1 ORDER BY 1"
  • both commands print the same numbers per hospital (option A: 1 → 100002, 2 → 20000, 3 → 10000)

9.5 End-to-end: a new registration reaches Analytics

  1. Sign in as h001.reg / Demo@1234 and register a patient (New Registration, fill the required fields, Save). Note the registration number shown (for example H001-REG2026...).
  2. Sign in as h001.reports, open Analytics, run "Patient Register (Report 1)" and search for the new patient (filter Patient Name contains ...).
  • the patient appears within about 1 minute (without real time) or within a few seconds (with start.bat cdc)
  • with real time: curl http://localhost:8083/connectors/patient-outbox/status shows "state":"RUNNING" twice
The test patient stays in the data. Delete it later as administrator if needed, or simply run restore.bat again.

9.6 Automated tests (optional, for developers)

Needs a JDK 21 installed on the computer (for example Eclipse Temurin 21) and the system running. The bundled Maven in tools\ is used; edit JAVA_HOME in env.bat to your JDK first.

test.bat                                   # 178 Java tests (about 8 minutes)
cd pr-ui
..\tools\node\npm ci                       # first time only (downloads the test libraries)
..\tools\node\npx playwright test          # 23 browser tests in Microsoft Edge (needs option A data)
  • "Tests run: ..., Failures: 0, Errors: 0" in every module and "BUILD SUCCESS"; Playwright prints "23 passed"

10. Access from other computers

The application port 8080 is open to the network (the databases are not). Other computers on the same network use the server's IP address:

ipconfig                                   # find the IPv4 address, e.g. 192.168.1.25
http://192.168.1.25:8080/patient-registration/

If it does not open, allow the port in Windows Defender Firewall (administrator PowerShell):

New-NetFirewallRule -DisplayName "Patient Registration 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Private
This is a proof of concept: demo passwords, no HTTPS. Do not expose it to the internet or use real patient data before production hardening (secrets, TLS, sign-on).

12. Update to a new version

backup.bat                 # safety copy of the data first
git pull                   # get the new version
deploy.bat                 # rebuild and replace only the application (databases keep running)
docker compose up -d       # re-run the set-up steps (new ClickHouse columns etc.); add --profile cdc if used
  • Database changes are applied automatically when the application starts; no manual SQL is needed.
  • Check afterwards with section 9. If the new version misbehaves: git checkout <previous commit>, deploy.bat, and if needed restore.bat with the backup.
  • After deploy.bat, the image date can be checked with docker image inspect patient-registration-app:latest --format "{{.Created}}"; it must be the current time.

13. Backup and restore

  • Backup: backup.bat → one file in backup\ with all patients, users, settings and saved reports (the reporting copy in ClickHouse is rebuilt from it, so it needs no backup).
  • Restore: restore.bat backup\<file>.dump (type YES) — replaces everything with the backup.
  • Move to another computer: deploy there (sections 3-6), copy the dump file into its backup\ folder (or commit it to the private repository), and run restore.bat.
  • Keep backups private: they contain patient records and users' password hashes.

15. Uninstall

docker compose --profile cdc --profile seed down        # remove containers, KEEP the data volumes
docker compose --profile cdc --profile seed down -v     # remove containers AND all data (cannot be undone)
docker image rm patient-registration-app:latest         # optional: free the application image

Then delete the project folder. Take a backup.bat first if the data may be needed again.

The .bat files are short wrappers; on Linux/macOS run the Docker commands directly in the project folder:

certutil -hashfile ... SHA256sha256sum backup/<file>.dump (macOS: shasum -a 256)

restore.bat on Linux/macOS (replaces all data):

docker compose stop app debezium
docker exec pr-postgres psql -U postgres -d postgres -c "DROP SCHEMA IF EXISTS identity, patientreg, reporting CASCADE"
docker exec -i pr-postgres pg_restore -U postgres -d postgres --no-owner --no-acl < backup/patientreg_full_2026-10-16_1726.dump
docker exec pr-clickhouse sh -c 'clickhouse-client --user admin --password "$CLICKHOUSE_PASSWORD" -q "TRUNCATE TABLE analytics.patient_report"'
docker compose up -d

17. One-page checklist

  • Docker Desktop installed and running, at least 4 GB memory for Docker, 10 GB free disk
  • Git installed; access to SPM-Technologies/Reports_Analytics
  • Ports 8080, 5432, 8123 (8083) free
  • git clone https://github.com/SPM-Technologies/Reports_Analytics.git → cd Reports_Analytics
  • .env reviewed (passwords changed if the computer is shared)
  • start.bat → wait for pr-app (healthy) (first time 8-15 min)
  • restore.bat backup\patientreg_full_2026-10-16_1726.dump → YES
  • optional: start.bat cdc for real-time reports
  • docker compose ps -a: all Up (healthy), set-up containers Exited (0)
  • sign in at http://localhost:8080/patient-registration/ as admin / Admin@1234
  • patient counts equal in PostgreSQL and ClickHouse (section 9.4)
  • a new registration appears in Analytics (section 9.5)
  • first backup taken with backup.bat
When every box is ticked, the deployment is complete and verified.
