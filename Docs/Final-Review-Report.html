2. How the review was done

  • Four reviewers worked independently and read-only (code, SQL, configuration, the running system: SELECTs, API calls, container state), each listing findings with evidence, severity and a fix.
  • Every finding was fixed in code, configuration or documents, or explicitly accepted as a documented limitation (section 7).
  • Each fix got a regression test where it can be tested automatically (FinalReviewTest, extended CustomisationTest, AdminScreensTest, CsvExporterTest, QueryBuilderTest).
  • Finally the whole project was copied without tools, build output and backups, started from empty volumes as a recipient would, and exercised end to end (section 5).

7. Accepted limitations (documented, not changed)

  • POC secrets in plain text (.env, property files), local users only, no TLS: by design for the local POC.
  • Database row security per user (all their hospitals); per-action checks are in Java (tested).
  • Sign-in audit rows carry no hospital (visible to super administrators); Aadhaar stored unencrypted and shown to users who may view patients; no forced change of the first admin password.
  • Concurrent edits of the same setting: last save wins. The internal patient id can be used inside formulas (no personal data).
  • App container runs as root; host tools needed for the test suites; PDF Unicode fonts skipped; crore-scale load test (stage 6) postponed.
