2. What was delivered

Stage 5a: sign-in and hospitals

  • Local users with BCrypt passwords, lock-out and throttling, form login with CSRF protection, change password.
  • Hospitals with codes; users with a role per hospital and several hospitals; switching the working hospital in the header.
  • Data isolation in four layers: PostgreSQL row-level security on every patient table, composite keys, permission checks per hospital, and a forced hospital filter in every ClickHouse query backed by a ClickHouse row filter.
  • Registration numbers per hospital and year (H001-REG2026 + 7 digits); departments per hospital; the same person at two hospitals stays two records.
  • Audit log; administration screens for users, hospitals, roles and the audit log; access changes apply at once.

Stage 5b: customisation without code

  • Roles: hospitals define their own roles from the list of permissions (new: share, manage settings).
  • Registration form: own fields of 8 types per section, hide optional standard fields, own dropdown values, departments and doctors per hospital.
  • Report fields: per field Normal / Masked / Hidden / Administrators only and own labels, applied everywhere in Analytics.
  • Report builder: own fields in reports (opt-in), calculated fields with a safe formula language, % of total / running total / rank / change, subtotals, top N + Others, conditions on totals, pivot, highlighting, drill-down.
  • Sharing: private or hospital-wide reports, dashboards and shared formulas.
  • Dashboards: up to 12 report tiles with filters for all tiles.
  • Downloads: hospital branding (title prefix, header, footer, logo) and allowed formats, for Analytics and the legacy reports.

3. Third-eye review of stage 5b and what was done

An independent reviewer read all stage 5b code and ran read-only checks against the live system. It confirmed as sound: no SQL injection through formulas or any new path, hospital isolation on all new tables and queries, CSRF on all new forms, JSP and React escaping, logo type detection, CSV formula-injection protection, idempotent migration.
